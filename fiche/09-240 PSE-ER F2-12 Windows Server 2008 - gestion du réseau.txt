WINDOWS SERVER 2008 : PRINCIPES DE LA GESTION DU RÉSEAU

1. SERVICES RÉSEAU EN COUCHES
Accès à distance (service « Réseau et accès distant ») : permet aux clients distants d'accéder aux serveurs et ressources (fichiers, imprimantes, services) comme s'ils étaient sur le réseau local. Deux types :
- Dial-up : connexion via téléphone ou infrastructure de télécommunications ; connexion temporaire physique ou virtuelle.
- VPN (réseau privé virtuel) : connexion virtuelle point à point via un réseau IP. Windows prend en charge SSTP (Secure Socket Transmission Protocol), tunnel récent qui encapsule PPP sur le canal SSL de HTTPS (port 443) et traverse la plupart des pare-feux qui bloquent PPTP ou L2TP/IPSec.
Accès à distance vs contrôle à distance : l'accès à distance est une connexion proxy vers le réseau ; le contrôle à distance exécute les applications sur un serveur et n'en présente que l'interface.

Active Directory : mise en œuvre Windows de services d'annuaire légers de type LDAP. Base de données d'objets représentant les ressources ; classes et attributs définis par un schéma ; objets hiérarchisés (conteneurs). API d'accès : API C de LDAP ; ADSI (interface COM au-dessus de LDAP, multi-langages, utilisable par WSH) ; MAPI (Exchange/Outlook) ; API SAM (ouverture de session, Msv1_0 pour NTLM et Kerberos) ; Net API (clients NT 4) ; API NTDS (SID/GUID, gestion et réplication).
Stockage : fichier %SystemRoot%\NTDS\Ntds.dit, répliqué sur chaque contrôleur de domaine. Service d'annuaire dans le processus LSASS ; moteur ESE (Extensible Storage Engine, alias JET Blue), bibliothèque Esent.dll ; mises à jour transactionnelles pour l'intégrité.

Répartition de charge réseau (Network Load Balancing) : incluse dans Windows Server 2008, basée sur le filtrage NDIS. Cluster de jusqu'à 32 ordinateurs (hôtes du cluster) ; adresses IP dédiées + une seule adresse IP virtuelle publiée. La demande cliente arrive à tous les hôtes, un seul répond ; chaque demande gérée par un et un seul hôte. Défaillance d'un hôte : la grappe redistribue les demandes ; un hôte de remplacement peut être ajouté. Conditions : protocoles pris en charge par la pile Windows TCP/IP ; capacité à gérer les demandes sur n'importe quel système (l'état partagé est géré par l'application, le NLB ne le distribue pas). Applications adaptées : serveur web de contenu statique, Windows Media, Terminal Server.

Système de fichiers distribué (DFS) et réplication DFS :
- DFS relie des machines à des partages via un espace de noms unique ; accès client transparent quelle que soit la localisation. La racine de l'espace de noms doit être un partage sur un serveur Windows. Équilibrage de charge et haute disponibilité par jeux de réplicats (FRS pour créer une réplique). Côté serveur : service Dfssvc.exe (exportation, topologie dans le registre ou Active Directory) + pilote Dfs.sys (recherche de topologie). Côté client : pilote Dfsc.sys (redirecteur SMB), fournisseur Ntlanman.dll.
- DFSR (réplication DFS) : réplique le contenu d'un partage DFS et le dossier SYSVOL (scripts de connexion, fichiers de stratégie de groupe). Réplication multi-maître distribuée. Jeu de réplicats = 2 systèmes ou plus reproduisant une arborescence selon un calendrier et une topologie (anneau, étoile, mesh) ; un ordinateur peut être membre de plusieurs jeux. Seuls les volumes NTFS (s'appuie sur le journal NTFS). Compression différentielle à distance (RDC) : seules les différences répliquées. Service Dfsr.exe, authentification RPC chiffrée, API Active Directory pour la configuration, interface WMI.

2. UTILITAIRES DE DIAGNOSTICS RÉSEAU
Moyens d'administration : script et Windows PowerShell, lignes de commandes, Netsh, Centre Réseau et partage.
Windows PowerShell : interpréteur et langage de script pour l'administration ; accepte et retourne des objets .NET (et non du simple texte). Applets de commande (>100, extensibles), utilisables seules ou combinées ; accès au Registre et aux certificats comme au système de fichiers.
Lignes de commandes : IPCONFIG, NETSTAT, TRACERT, PATHPING, PING, NBTSTAT, NETDIAG.
- IPCONFIG : sans paramètre, affiche adresses IPv4/IPv6, masque et passerelle par défaut de toutes les cartes ; actualise DHCP et le nom de domaine. /all = détail, /? = aide.
- NETSTAT : connexions TCP actives, ports d'écoute, statistiques Ethernet, table de routage IP, statistiques IPv4 (IP, ICMP, TCP, UDP) et IPv6.
- PING (Packet INternet Groper) : requête ICMP echo ; temps de réponse, état de la connexion ; diagnostic de connectivité ; adresse IP ou nom.
- TRACERT : route d'un paquet IP ; contrôle du TTL (1, puis 2, 3...) ; chaque routeur renvoie « durée de vie dépassée lors du transit » ; chaque requête répétée trois fois ; requête inverse pour le nom de chaque adresse.
- PATHPING : plus rapide ; requêtes ICMP à TTL croissant comme TRACERT, mais affichage immédiat des résultats, puis attente de la réponse du dernier hôte pour les statistiques.
- NBTSTAT : visualise et manipule le cache de noms NetBIOS (600 s par défaut) ; paramètres sensibles à la casse.
- NETDIAG : batterie de tests sur presque toutes les fonctions réseau (navigateur, DNS, IPCONFIG, IPX, Kerberos, LDAP, NETSTAT, Netware, Route, WAN, WINS, Winsock) ; outil de premier secours ; /q (silencieux), /v (documenté).
Netsh (Network Shell) : ligne de commande, commandes hiérarchisées ; configure et affiche l'état des rôles et composants (local ou distant) ; équivalent MMC + réseaux purement IPv6, avec ponts ou RPC ; utilisable dans scripts et fichiers batch.
Centre Réseau et partage : regroupe la gestion du réseau : intégrité graphique du réseau, partage de dossiers, nouvelles connexions distantes (accès à distance ou VPN), connexions sans fil. Accès via Panneau de configuration ou icône Réseau de la zone de notification.

3. RÉSOLUTION DE NOMS NETBIOS
Trois méthodes : diffusion (petits réseaux non routés), fichier local LMHOSTS (emprunté à Unix), base centralisée WINS (propre à Microsoft). Sous Windows, les noms sont résolus en priorité par le DNS, puis par NetBIOS si le DNS échoue ; LLMNR est un mécanisme secondaire de secours.
Diffusion : les machines se découvrent en « criant » leur nom et leur adresse ; trafic incessant. Les diffusions NetBIOS ne passent pas les routeurs (un domaine de diffusion = segment sans routeur) ; NetBIOS lui-même (ports 137 et 139) peut être routé. Inscription de nom : au démarrage, l'ordinateur diffuse une inscription de nom NetBIOS pour vérifier l'unicité. Résolution : NetBT consulte d'abord le cache de noms ; sinon jusqu'à trois requêtes sur le sous-réseau local ; l'hôte ayant enregistré le nom répond positivement.
LMHOSTS : fichier texte statique (adresses IP + noms), insensible à la casse, dans %systemroot%\System32\Drivers\etc (avec HOSTS, SERVICES, PROTOCOL, NETWORK, QUOTES ; exemple LMHOSTS.sam). Paramètres en majuscules précédés de # (#PRE, #DOM ; # sert aussi de commentaire). À n'utiliser qu'en dernier recours (tables statiques = pièges si non mises à jour). Peut être centralisé, sans empêcher un fichier local.
WINS (Windows Internet Name Service) : ancêtre d'Active Directory et du DNS (jusqu'à Windows 2000 ; conservé pour Windows 95/98). Base de mappages noms NetBIOS / adresses IP. Deux fonctions : inscription de nom et résolution de nom. Un client WINS est configuré avec l'adresse d'au moins un serveur (principal + secondaire).
- Inscription : requête au serveur ; si pas d'homonyme, réponse positive, ajout à la base, échéance de réinscription (valable six jours par défaut) ; si homonyme avec autre IP, le serveur interroge le titulaire actuel avant de trancher ; renouvellement à mi-intervalle ; libération à la fermeture normale (intervalle d'extinction). Inscription non conservée si : libération sans réinscription à temps, non-renouvellement, serveur WINS indisponible au renouvellement, déconnexion anormale.
- Résolution : NetBT.sys envoie une requête de recherche ; un nom avec un point ou de plus de 16 caractères est traité comme un nom d'hôte DNS (via TCPIP.SYS). Le serveur renvoie l'adresse IP si l'enregistrement est actif ; requête au serveur secondaire si le principal est indisponible.
- Pratique : plusieurs serveurs par zones géographiques ; chaque serveur est propriétaire des enregistrements de ses clients et les réplique vers ses partenaires de réplication. Modes de réplication : émission (push : le serveur envoie ses mises à jour) et collecte (pull : les partenaires viennent les chercher à intervalles réguliers).
