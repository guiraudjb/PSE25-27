WINDOWS SERVER 2008 : GESTION DE LA MÉMOIRE

1. CONCEPT DE MÉMOIRE VIRTUELLE
Windows met en œuvre une mémoire virtuelle activée à la demande : illusion d'une mémoire physique plus grande que la réalité. Double hiérarchie : cache / mémoire principale et mémoire principale / mémoire auxiliaire (disque).
Repose sur la page : programmes et données segmentés automatiquement en blocs de longueur fixe. Adresses translatables (déplacement relatif dans la page). Seules les parties actives sont en mémoire principale ; les pages nécessaires sont chargées à la demande, les inactives recouvertes (swapping). Translation dynamique des adresses. La taille d'une mémoire virtuelle n'est limitée que par les capacités d'adressage du système.

2. DU 32 BITS AU 64 BITS
Architecture définie par la taille des registres généraux (GPR). 1985 : Intel 80386, premier 32 bits. 2003 : AMD Athlon 64, premier 64 bits pour PC sous Windows (compatible x86 32 bits). Intel : Itanium (IA-64) entièrement 64 bits, incompatible avec l'existant (OS et applications 64 bits dédiés, peu de succès) ; puis EMT64 / x64 (registres 32 bits + extensions 64 bits, OS 32 ou 64 bits sur le même serveur).
Un processeur 64 bits n'adresse pas réellement 64 bits : 36 à 40 bits en pratique (AMD K8/K10 : 40 bits = 1 To ; Intel Core 2 : 36 bits). Windows Server 2008 64 bits gère 128 Go ; il n'exécute pas les programmes 16 bits, exécute les 32 bits dans WoW64 (couche de compatibilité, registres 32 bits, impact négligeable).
Espace d'adressage virtuel : 32 bits -> 2 Go par application. x64 (adressage virtuel sur 43 bits) -> 8 To pour le noyau et 8 To pour les processus 64 bits ; une application 32 bits passe de 2 Go à 4 Go. Indicateur /LARGEADDRESSAWARE (mode PAE) requis au compilateur pour qu'une application 32 bits utilise 4 Go ; commutateur /3GB non pris en charge en 64 bits.

3. GESTIONNAIRE DE MÉMOIRE
Deux rôles : allouer l'espace virtuel du processus et le traduire en mémoire physique ; paginer vers le disque quand la mémoire est surengagée. Services : fichiers mappés (objets section), copy-on-write, grands espaces clairsemés.
Chaque processus voit son propre espace virtuel (pas d'accès au noyau, aux autres processus, ni à la mémoire physique). Pages indivisibles de 4096 octets. Seul le noyau accède à la mémoire physique. Au lancement : mapping du code et des données depuis l'image PE du fichier exécutable, de la pile (paramètres, variables locales, adresses de retour ; agrandie automatiquement par le noyau), du tas (allocation dynamique ; agrandi par la bibliothèque C), des DLL. Sécurité : les mappings ne doivent pas se chevaucher (tas qui monte / pile qui descend).

4. CARTOGRAPHIE DE LA MÉMOIRE VIRTUELLE
Trois catégories : données du processus, de la session, du système.
Espace système : image de l'OS + HAL + pilotes de démarrage ; hyperspace (mapping de la liste des processus, mapping temporaire de pages) ; Working Set List ; cache système (fichiers ouverts mappés) ; réserve paginée (déplaçable entre mémoire et disque ; 2 sur monoprocesseur, 4 sur multiprocesseur pour réduire les blocages) ; réserve non paginée (garantie en permanence en mémoire physique, accès sans E/S de pages) ; PTE système (espace E/S, piles noyau) ; informations de crash ; mémoire HAL.
Deux tailles de pages selon l'architecture (petite / grande ; la grande accélère la traduction d'adresses).

5. PAGINATION
Le gestionnaire de pages (pager) traite les défauts de page, maintient les structures, protège les pages. TLB (Translation Look-aside Buffer) : mémoire associative de couples page virtuelle / page physique.
Pagination à la demande avec regroupement : au défaut de page, chargement de la page demandée + quelques pages voisines (principe de localité). Stratégie de placement (case libre si mémoire non pleine), sinon stratégie de remplacement (FIFO local : retire la page chargée depuis le plus longtemps). Jeu de pages de travail (working set) : ensemble des pages physiques d'un processus, taille minimale attribuée à la création.
Base de données des pages physiques : chaque entrée = une case ; six états (Valide, À zéro, Libre, En attente, Modifié, Mauvais) ; cinq listes des pages non utilisées. Thread modified page writer : réveillé sous un seuil, écrit les pages modifiées sur disque et les place en attente. Automatic working-set trimming quand les pages modifiées deviennent trop nombreuses. Sécurité C2 : threads utilisateur ne reçoivent que des pages à zéro.

6. PROCESSUS ET THREADS
Noyau WIN32 (32 bits) / WIN64 (64 bits, fonctionnalités quasi identiques, applications portables). Processus = instance d'une application active ; processus racine (père) et processus fils ; représenté par un block d'attributs + structures de données (dans l'espace système), sauf le PEB (Process Environment Block, dans l'espace du processus). PID visible dans le Gestionnaire de tâches.
IPC : le plus souvent via des fichiers mappés en mémoire. SMP : chaque processeur gère une liste de processus. Changement de contexte (ordonnanceur) : suspendre P0, mettre à jour son PCB, restaurer le PCB de P1, reconfigurer l'espace mémoire et la MMU, démarrer P1.
Thread (tâche) : entité programme au sein d'un processus ; il faut au moins un thread (principal) pour exécuter du code ; composé de registres, deux tas (kernel mode / user mode), une zone TLS (Thread Local Storage), un identifiant, éventuellement un contexte de sécurité. Threads = « processus légers » (pas d'espace mémoire propre, ressources partagées). Un processus sans thread actif est éliminé.
Ordonnancement : temps partagé depuis Windows 3.1 ; WIN32 ajoute des priorités préemptives, 32 niveaux (0 à 31). Un thread actif préempte immédiatement tout thread de priorité inférieure ; entre threads de même priorité, round robin (tranche fixe de CPU). Priorité implémentée sur les threads (pas les processus), combinée à une classe de priorité du processus (7 classes, fixée à la création).

7. GESTION DES DISQUES
Style de partition : MBR (Master Boot Record) sur tous les x86/64 ; volumes jusqu'à 4 To, 4 partitions principales (ou 3 + 1 étendue avec lecteurs logiques). GPT (GUID Partition Table) sur Itanium et x86/64 récents ; volumes jusqu'à 18-28 Eo, 128 partitions, tables de partition primaire et de sauvegarde redondantes ; conseillé au-delà de 2 To. Itanium exige un disque GPT avec partition EFI.
Disque de base : partitions principales/étendues, lecteurs logiques -> volumes de base (extensibles si NTFS, dans un espace contigu). Disque dynamique : volumes s'étendant sur plusieurs disques (agrégés, fractionnés) et volumes à tolérance de pannes (miroir, RAID-5). Cinq types de volumes dynamiques : simple, fractionné, agrégé par bandes, en miroir, RAID-5. Jusqu'à 2000 volumes dynamiques (32 recommandés). Non pris en charge sur portables, disques amovibles USB / IEEE 1394, bus SCSI partagés. Outils : Gestion des disques, DiskPart.exe, mountvol /p. La conversion MBR <-> GPT n'est possible que si le disque est vide.
Cluster (unité d'allocation ou bloc) : plus petite unité de disque gérée par l'OS, constituée d'un ou plusieurs secteurs ; un fichier occupe un ou plusieurs clusters. Cluster plus grand = plus de gaspillage possible mais moins d'entités à gérer.
