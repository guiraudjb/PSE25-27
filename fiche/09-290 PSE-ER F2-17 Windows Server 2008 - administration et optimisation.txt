WINDOWS SERVER 2008 : ADMINISTRATION ET OPTIMISATION DU SYSTÈME

Deux familles d'outils : interface graphique et ligne de commande. La liste d'outils a été simplifiée (moins d'outils, optimisés, nouveaux ajoutés).

1. OUTILS D'ADMINISTRATION GRAPHIQUES
Trois principaux : le Gestionnaire de serveur, la console MMC (et ses composants enfichables), l'accès distant.
Gestionnaire de serveur : outil local principal, centralise la gestion et la configuration : configuration du serveur, ajout/suppression de rôle ou fonctionnalité, état d'un rôle ou service, événements, pilotes et matériel, goulets d'étranglement et optimisation, stockage, sécurité du pare-feu, tâches planifiées, utilisateurs locaux, dépannage.
Rôles, services de rôle, fonctionnalités : un rôle regroupe des fonctions serveur ; un service de rôle est un sous-ensemble d'un rôle (un rôle fonctionne dès que plusieurs services de rôle sont activés) ; une fonctionnalité complète les possibilités (35 par défaut sous 2008, 41 sous R2 ; aucune installée à l'installation ; installation manuelle ou automatique avec un rôle).
Console MMC (Microsoft Management Console) : console commune hébergeant des composants logiciels enfichables ; permet l'administration à distance, la délégation, le regroupement logique des outils.
- Consoles préconfigurées (installées par défaut ou avec un rôle) / personnalisées (créées par l'administrateur ; combiner un ou plusieurs composants, enregistrer, distribuer, fournir sur mesure lors de la délégation ; ex. cacher l'option de suppression à un administrateur de comptes).
- Composants enfichables autonomes (tâches administratives par eux-mêmes) / d'extension (complémentaires, ne fonctionnent qu'avec un autonome ; seules les extensions compatibles sont affichées). Extension de fichier : .msc.
- Modes : Auteur (défaut, sans restriction) / Utilisateur (restreint ; délégation, partage). Trois types d'accès Utilisateur : accès total, accès limité avec fenêtres multiples, accès limité avec fenêtre unique.
- Création d'une console : Démarrer -> mmc -> Fichier -> Ajouter/Supprimer un composant logiciel enfichable.
RSAT (Remote Server Administration Tools) : composants enfichables pour gérer à distance rôles et fonctionnalités de Windows Server 2008 ; remplace l'adminpak ; natif seulement sous 2008 R2 (téléchargement sinon) ; configuration via le Gestionnaire de serveur (Ajout de fonctionnalités). Outils pour les rôles (AD CS, AD LDS, DHCP, DNS, fichiers, NPAS, Terminal Server, UDDI) et pour les fonctionnalités (BitLocker, clustering, GPMC, NLB, SMTP, gestionnaire SAN, WSRM).
Administration à distance (version Terminal Server réservée à l'administration) : activation sur le serveur + client requis ; deux administrateurs simultanés sans licences supplémentaires ; accès à tout le serveur ; protocole RDP (Remote Desktop Protocol) amélioré.

2. OUTILS D'ADMINISTRATION EN LIGNE DE COMMANDE
- ServerManagerCmd : gère rôles, services de rôle et fonctionnalités (-q liste, -p fichier XML, -install, -remove, -v version, -? aide).
- PowerShell : options -PSConsoleFile, -Version, -NoLogo, -NoExit, -Sta, -NoProfile, -NonInteractive, -InputFormat / -OutputFormat (Text ou XML CLIXML), -WindowStyle, -EncodedCommand (Base64), -File, -ExecutionPolicy, -Command, -Help.
- Invite de commande : centaines de commandes, scripts batch ou vbs (Bloc-notes sans caractères accentués ; Wordpad en enregistrant en MS-DOS).
- ocsetup (remplace Sysocmgr) : installe/supprime des packages MSI ou composants optionnels ; pkgmgr : installe/supprime/met à jour des packages. Plus difficiles à mettre en œuvre que le Gestionnaire de serveur, mais seuls moyens sous Server Core. Options ocsetup : /log, /norestart, /passive, /quiet, /unattendfile, /uninstall, /x. Options pkgmgr : /ip, /l (journaux dans %WINDIR%\logs\cbs\cbs.log ; Setupact.log complet, Setuperr.log erreurs), /iu.
- Netsh : configurer et surveiller des ordinateurs locaux ou distants ; commandes hiérarchisées par contexte (advfirewall, interface, ipsec, ras, trace, wlan, winsock...) ; utilisable en scripts.
- WinRS / WinRM : WinRM (Windows Remote Management) est le service à activer sur l'ordinateur distant ; WinRS (Windows Remote Shell) y exécute des commandes. Messages chiffrés par défaut (clés Kerberos ou NTLM ; -unencrypted ; ignoré en HTTPS). Options : -r (point de terminaison), -u / -p, -d (répertoire), -env, -noprofile, -allowdelegate, -compression (désactivée par défaut), -usessl.
- WMIC (Windows Management Instrumentation Command-line) : interroger des objets WMI via des alias ; natif sous Windows Server 2008. Paramètres /NAMESPACE, /NODE, /USER, /PASSWORD, /OUTPUT, /TRACE, /RECORD...

3. SAUVEGARDE ET RESTAURATION
Fonctionnalités : clichés instantanés de dossiers partagés ; outils de sauvegarde de Windows Server (console MMC, Wbadmin en ligne de commande, commandes PowerShell) ; environnement de récupération Windows (restauration complète du PC, diagnostic mémoire, invite de commandes). Ntbackup.exe supprimé.
La sauvegarde peut porter, localement ou à distance, sur : l'intégralité du serveur (tous les volumes), des volumes, l'état du système, des dossiers ou fichiers ; de manière manuelle ou planifiée.
WinRE : environnement de récupération et de dépannage, accessible via « Options de récupération du système » de l'assistant d'installation ; récupération (à partir de sauvegardes préalables) du système d'exploitation, de l'état du système, des volumes, des applications et données, du catalogue de sauvegardes, des fichiers et dossiers locaux.

4. SÉCURISER UN CONTRÔLEUR DE DOMAINE
Système de fichiers : NTFS obligatoire (jamais FAT/FAT32) ; toujours formater en NTFS à l'installation. convert <unité> /fs:ntfs pour convertir a posteriori, mais les ACL ne sont alors pas appliquées automatiquement (contrairement à un formatage NTFS d'origine).
Mot de passe administrateur (ANSSI) : 12 caractères minimum (16 si possible), types différents, sans lien avec soi, changé régulièrement, non retenu par les logiciels, non stocké près de l'ordinateur, limiter les tentatives.
Option Core : installation minimaliste (éléments et packages fondamentaux ; ni framework ni bureau) ; administration locale uniquement en ligne de commande ; installation demandant 4 informations (langue/paramètres régionaux, clé de licence, acceptation du contrat, disque/partition cible).
Comptes : désactiver ou supprimer régulièrement les comptes inutiles ; compte invité désactivé par défaut (le vérifier). Compte administrateur : le renommer par un nom non évocateur, créer un leurre « administrateur » sans privilège avec audit des ouvertures de session, désactiver le vrai compte (comptes de domaine et locaux).
Fichiers et répertoires : ACL NTFS pour restreindre précisément les actions ; propriétés dans l'onglet Sécurité.
Registre : accès distant limité par défaut aux Administrateurs ; clé \winreg sous HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers pour ajuster (Contrôle Total au groupe Administrateurs, retirer les autres).
Politique de mot de passe et verrouillage de compte : via la console de gestion des stratégies de groupes (Stratégie de mot de passe, Stratégie de verrouillage de compte).
Cacher une machine : valeur Hidden (REG_DWORD) = 1 sous ...\Services\LanmanServer\Parameters (environnements hautement sécurisés).
Partages : supprimer les partages inutiles ; nouveaux partages créés par défaut avec « Contrôle Total » pour « Tout le monde » -> restreindre. Désactiver les partages administratifs : AutoShareServer (REG_DWORD) = 0 sous ...\Services\lanmanserver\parameters.
Post-configuration : antivirus à jour (ne détecte que les virus connus, pas les attaques 0-day) ; service packs (chacun inclut les mises à jour des précédents) ; Windows Update (mises à jour importantes le 2e ou 4e mardi du mois ; vérifier une fois par semaine). Référentiels : ssi.gouv.fr, cert.ssi.gouv.fr.
Configuration de la sécurité : composant « Configuration et analyse de la sécurité » (console MMC personnalisée uniquement), basé sur un modèle de sécurité (composant « Modèle de Sécurité ») ; version ligne de commande secedit.exe. Options : forcer Ctrl-Alt-Suppr, Verrouiller la station / Se déconnecter, mot de passe à la sortie de veille, suppression de pagefile.sys à l'arrêt (Éditeur de Stratégie Locale, non actif par défaut, empêche l'extraction d'informations du fichier de pagination, arrêt plus long), ne pas afficher le nom du dernier utilisateur.
Audit (Stratégie de sécurité locale -> Stratégies locales -> Stratégies d'audit) : accès au service d'annuaire, accès aux objets, utilisation des privilèges, gestion des comptes, suivi des processus, événements de connexion, événements de connexion aux comptes, événements système, modifications de stratégies. Redémarrage nécessaire.
BitLocker : chiffrement de disque de tout un volume de l'OS ; utilise le TPM (module de plateforme sécurisée) et assure l'intégrité des composants de démarrage. Fonctionnalité « Chiffrement de lecteur BitLocker » à installer (redémarrage) ; mot de passe de récupération à enregistrer (plusieurs supports possibles). Peut impacter les performances.
EFS (Encrypting File System) : depuis Windows 2000 ; partitions NTFS v.5+ ; transparent. Algorithme asymétrique (clé privée/publique) pour encoder les clés symétriques qui chiffrent les fichiers. Agent de récupération obligatoire (départ d'un employé, perte de clé privée). Clés dans un pool de mémoire non paginé du noyau (non extractibles du fichier de pagination). Cryptage 56 bits par défaut, jusqu'à 128 bits ; fichier compressé jamais chiffré (et inversement). Windows Server 2008 : certificats sur carte à puce, chiffrement par utilisateur du cache côté client, options GPO, Assistant de changement de clé. Partage impossible pour un fichier d'un dossier crypté.
IPSec : protection des paquets IP, sécurité de bout en bout. Déployable via Active Directory ou la Sécurité Locale. Agent de stratégie IPSec = service dans lsass.exe (visible dans le composant MMC Services), démarré à la mise en route ; récupère la stratégie dans Active Directory ou le registre local (clés ...\Services\PolicyAgent\Policy\Cache ou \Local). Moniteur de sécurité IPSec : ipsecmon.exe ; paquets AH et ESP visibles avec l'analyseur de trames ; logs dans ipsecpa.log.
Exécuter en tant que : tester des réglages avec un autre compte que celui connecté (similaire à su sous Unix) ; clic droit sur l'icône de l'application.

5. LES PARTAGES
Partage d'une ressource (imprimante, dossier, disque) pour l'accès par le réseau ; toute l'arborescence sous le point de partage est accessible (restrictions possibles). Syntaxe : \\NomDuServeur\NomDuPartage ; ajouter $ à la fin du nom pour cacher le partage. Création via l'assistant (clic droit -> Partager ; niveau par défaut « Lecteur ») ou l'outil Gestion de l'ordinateur (nœud « Partages »). Autorisations de partage (analogues aux permissions NTFS) : Contrôle Total, Modifier, Lire (autorisation ou refus). Propriétés avancées : onglet Partage -> Partage Avancé.

6. CLICHÉS INSTANTANÉS
Copies à un instant donné de fichiers de ressources partagées ; récupération sans aide d'un fichier supprimé ou écrasé par inadvertance, comparaison de versions. Inclus dans la console MMC de gestion des dossiers partagés. Activation uniquement pour un volume entier ; ne remplace pas les sauvegardes régulières. Configuration : clic droit sur le lecteur -> « Clichés instantanés », ou commande vssadmin.

7. QUOTAS DE DISQUE
Limiter la quantité de données par utilisateur pour répartir l'espace équitablement. S'appliquent uniquement aux volumes NTFS, indépendamment des structures de dossiers : le quota d'un volume s'applique collectivement à tous ses dossiers ; chaque volume d'un disque a son quota indépendant ; un volume s'étendant sur plusieurs disques a un quota global. Activation : propriétés du lecteur -> onglet « Quotas » (désactiver ne supprime pas les données). Windows peut empêcher toute nouvelle utilisation au dépassement de la limite (et enregistrer un événement) et/ou enregistrer un événement au dépassement du niveau d'avertissement.

8. PERFORMANCE, MÉTROLOGIE, OPTIMISATION
Observateur d'événements (Outils d'administration) : journaux Applications (par les applications), Système (par Windows), Sécurité (audits succès/échecs), Événements transmis (autres ordinateurs), Configuration (installation d'applications), Applications et services (sous-journaux Administration, Opérationnel, Analyse, Débogage - visibles si « Afficher les journaux d'analyse et de débogage »). Taille max par défaut 512 Ko ; options : remplacer les événements, remplacer seulement les plus anciens (X jours), ne pas remplacer (nettoyage manuel). Enregistrement au format .evt (pour l'observateur) ou texte. Vues personnalisées (filtre ou XML).
Moniteur de fiabilité et de performances (remplace l'analyseur de Windows Server 2003) : analyseur de performances, moniteur de fiabilité, collecteurs, rapports.
- Moniteur de ressources : visualisation et analyse en temps réel du processeur, des disques, du réseau et de la mémoire (vision centralisée pour l'optimisation) ; lancement perfmon /res.
- Analyseur de performances : surveiller et mesurer l'activité d'un ou plusieurs ordinateurs ; objets associés à des compteurs, éventuellement plusieurs instances (ex. bi-processeur = 2 instances Processeur) ; graphes, alertes (dépassement de seuil : journal d'alerte, journal d'application, alerte réseau, exécution d'un programme), rapports, archives. Export au format HTML ou TSV. Goulets d'étranglement : une activité disque élevée peut venir d'une fragmentation, d'un transfert trop long, ou d'un manque de RAM (pagination excessive).
- Moniteur de fiabilité : rapports de stabilité classés (installation/désinstallation de logiciels, défaillances d'applications, défaillances matérielles, échecs Windows, échecs divers).
- Collecteurs de données : quatre types - personnalisés (configurables), système (prédéfinis, non modifiables), sessions de suivi d'événements, sessions de traces d'événements Startup (au démarrage).
Gestionnaire des tâches (Ctrl+Alt+Suppr ou Ctrl+Maj+Échap) : démarrer/fermer des applications, tuer des processus, données processeur/mémoire. Onglets : applications et leur état, processus, services (activer/désactiver), performances (mémoire, processeur, moniteur de processus), charge réseau par carte, utilisateurs connectés (déconnexion).

9. SNMP (Simple Network Management Protocol)
Standard Internet pour la gestion de nœuds de réseaux hétérogènes TCP/IP. Agents SNMP sur les nœuds -> informations d'état dans des bases MIB (Management Information Base) -> collectées par une station NMS (Network Management Station). Usages : configurer des périphériques distants, surveiller les performances, détecter erreurs et accès inappropriés, auditer l'utilisation. Sous Windows Server 2008 : fonctionnalité non installée par défaut (Gestionnaire de serveur -> Fonctionnalités -> Service SNMP). Configuration via la console MMC Services (clic droit sur Services SNMP -> Propriétés) : onglet Agent (contact, type de services), onglet Interruptions (communautés ; « publique » par défaut), onglet Sécurité (ne répondre qu'aux communautés explicitement identifiées).

10. WMI (Windows Management Instrumentation)
Mise en œuvre pour Windows de l'initiative WBEM de la DMTF, étendant le modèle de données CIM (Common Information Model). Interface unique, cohérente, extensible et orientée objet pour configurer, gérer et interroger les ressources d'un ordinateur (localement ou à distance de façon transparente). Fonctionnalités : API d'écriture de script uniforme, administration à distance, recherche et navigation (énumération des classes), fonctionnalité de requête (données traitées comme une base relationnelle, requêtes SQL), publication d'événements et abonnements.
Outils : WMI Control (wmimgmt.msc, console MMC de configuration), WMI Tester (wbemtest.exe, outil graphique), WMI Commandline (wmic.exe, ligne de commande) ; outil tiers WMIEXPLORER.

11. COMMANDES NET
Nombreuses actions d'administration des serveurs et des connexions réseau, en ligne de commande ou dans des fichiers BATCH.

12. COMMUNICATION - SERVICES TERMINAL SERVER
Le rôle Services Terminal Server permet d'accéder à des programmes Windows installés sur un serveur, ou au Bureau Windows, depuis un réseau d'entreprise ou Internet. L'exécution a lieu sur le serveur ; seuls clavier, souris et affichage transitent ; chaque utilisateur ne voit que sa session. Avantages : déploiement rapide et centralisé, moins de bande passante pour les applications distantes, meilleures performances pour les succursales.
Services de rôle : Terminal Server (héberge programmes ou Bureau Windows), TS Web Access (programmes RemoteApp et Bureau à distance via un site Web), Gestionnaire de licences des services Terminal Server (licences d'accès client par périphérique ou utilisateur), Passerelle des services Terminal Server (accès distant à des ressources internes depuis Internet), TS Session Broker (équilibrage de charge des sessions et reconnexion à une session existante).
RemoteApp (TS RemoteApp) : programme accessible à distance qui se comporte comme s'il était local ; intégré au Bureau du client, dans sa propre fenêtre redimensionnable avec sa propre entrée dans la barre des tâches. Plusieurs RemoteApp d'un même serveur partagent la même session. Accès via TS Web Access (lien web), fichier .rdp, ou package Windows Installer (.msi) / association d'extension. Signature numérique des .rdp (certificat SSL, de signature de code ou de signature RDP dédié) pour éviter les fichiers falsifiés ; nécessite RDC 6.1.
Passerelle des services Terminal Server : encapsule RDP dans HTTPS et transmet le trafic vers le port 443 (tunnel TLS/SSL) au lieu du port 3389 souvent bloqué ; connexion chiffrée aux ressources internes derrière pare-feu et NAT sans VPN, connexion RDP point-à-point, stratégies d'autorisation (qui, vers quelles ressources, appartenance à des groupes AD, redirection de périphérique/disque, carte à puce ou mot de passe). Peut utiliser NAP et Microsoft ISA Server (hébergement sur réseau privé, ISA sur le réseau de périmètre).
TS Session Broker : suivi des sessions d'une batterie à charge équilibrée (ID de session, utilisateur, serveur hébergeur) ; redirige un utilisateur ayant une session existante vers son serveur ; avec l'équilibrage activé, dirige les nouveaux utilisateurs vers le serveur ayant le moins de sessions.
Connexion Bureau à distance : accéder à un ordinateur Windows depuis un autre (même réseau ou Internet) ; l'ordinateur cible doit être allumé, connecté, Bureau à distance activé, avec autorisations. Installée par défaut sous Windows Server 2008. Deux connexions à distance simultanées maximum, sans licence d'accès client Terminal Server. Les membres du groupe Administrateurs local peuvent se connecter sans figurer dans la liste. Pour de l'administration seule, activer le Bureau à distance suffit (pas besoin d'un serveur Terminal Server).
Paramètres RemoteApp : RDP personnalisés (redirection audio...) ; « Exiger l'authentification du serveur » -> certificat SSL nécessaire pour des clients Windows XP SP2 / Server 2003 SP1 (pas de certificat auto-signé) ; inutile en intranet si tous les clients sont Windows Vista / Server 2008 (authentification au niveau du réseau, NLA).
