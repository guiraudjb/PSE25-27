WINDOWS SERVER 2008 : SYSTÈMES DE FICHIERS NTFS ET AUTORISATIONS

1. SYSTÈMES DE FICHIERS SUPPORTÉS
Rôle : organiser et optimiser l'implantation des données sur les disques (goulet d'étranglement : accès en ms contre ns en mémoire). Windows Server 2008 supporte FAT, FAT32 et NTFS (natif). Choix selon l'OS, la sécurité, la taille des partitions et fichiers, le multiboot.
MBR (secteur de démarrage) : cylindre 0, tête 0, secteur 1 ; contient la table des partitions, le code d'amorçage (bootstrap) et les informations du disque (fabricant, numéro de série, octets/secteur, secteurs/cluster). Sans lui le disque est inutilisable : cible privilégiée des virus. Appelé « boot manager » sous Windows NT.
FAT : la File Allocation Table est un tableau, une case par cluster, indiquant si le cluster est utilisé et pointant vers le suivant (chaîne FAT). Valeurs : 0000 non utilisé, FFF7 défectueux, FFF8-FFFF fin de fichier. Deux copies stockées pour la récupération. Les répertoires stockent nom, taille, date, attributs, premier cluster.
FAT16 : entrées 16 bits, 65 535 clusters max, partition de 2 Go max (clusters de 32 ko). FAT32 : entrées 32 bits, jusqu'à 268 millions de clusters, partitions jusqu'à 2 To, clusters plus petits (4 ko) donc moins de gaspillage.

2. NTFS
Système natif de Windows 2008. Avantages : noms de fichiers de 255 caractères (sauf * ? ^ ; < > |), fichiers et partitions jusqu'à 16 Eo (offsets 64 bits), attributs étendus, sécurité (autorisations, chiffrement EFS), compression fichier par fichier (depuis NT 3.51, sans logiciel tiers), indexation, mise à jour des liens lors d'un déplacement de volume. Lisible uniquement par les systèmes Windows NT/2000/2003/XP/2008.
Structure : partitions listées dans le MBR ; secteur d'amorçage du volume (formaté différemment) ; fichiers système répartis n'importe où sur le volume (un dommage localisé n'empêche pas tout l'accès). Adressage : LCN (Logical Cluster Number, depuis le début du volume) et VCN (Virtual Cluster Number, offset dans un fichier).
MFT (Master File Table) : structure de stockage primaire ; un enregistrement (record) par fichier, regroupant des attributs. Un petit fichier (< ~1500 octets) tient entièrement dans son enregistrement (attributs résidents) ; sinon les données vont dans des clusters externes (extensions, attributs non résidents). 16 premiers enregistrements = metafiles créés automatiquement : $MFT (0), $MFTMirr (1, copie de secours), $LogFile (2, journal des transactions), $Volume (3), $AttrDef (4), $. (5, racine), $Bitmap (6, clusters utilisés), $Boot (7), $BadClus (8), $Quota (9, NTFS 5), $UpCase (10). Localisation de la MFT et de sa copie dans le secteur de boot ; copie du secteur de boot au centre logique du disque.

3. CONTRÔLE D'ACCÈS
Processus autorisant utilisateurs, groupes et ordinateurs à accéder aux objets. Éléments : objets (fichiers, imprimantes...), jetons d'accès (identité du sujet, recréés à chaque connexion), ACL / ACE, sujets (utilisateurs ou applications), autorisations, droits et privilèges.
Le sous-système de sécurité compare le jeton d'accès aux ACE de l'objet ; il parcourt l'ACL jusqu'à une ACE qui autorise ou refuse ; à la fin de l'ACL sans réponse explicite -> accès refusé (refus implicite).
Autorisations : type d'accès accordé sur un objet ou une propriété ; à affecter de préférence aux groupes (meilleures performances). Communes à la plupart des objets : Lecture, Modification, Changement de propriétaire, Supprimer. Un autre type existe : les autorisations de partage (onglet Partage).
Propriétaire : par défaut le créateur ; il peut toujours modifier les autorisations.
Héritage : les objets d'un conteneur héritent des autorisations héritables du conteneur à leur création (seules celles marquées pour l'héritage). Autorisations explicites (définies directement) vs héritées (transmises par le parent). Les explicites sont prioritaires sur les héritées, y compris sur une Refuser héritée. En cas d'héritage contradictoire de parents différents, le parent le plus proche l'emporte.
Droits d'utilisateur : liés au compte (ouverture de session interactive, sauvegarde...), gérés via la Stratégie de sécurité locale (Attribution des droits utilisateur) ; différents des autorisations liées aux objets.
Audit des objets : nécessite d'activer « Auditer l'accès aux objets » (Stratégie d'audit) ; événements visibles dans le journal de sécurité via l'Observateur d'événements.

4. GESTION DES AUTORISATIONS
Descripteur de sécurité : ensemble d'informations de contrôle d'accès créé avec l'objet ; contient la DACL (Discretionary ACL : groupes/utilisateurs autorisés et accès accordés) et la SACL (System ACL : informations d'audit — qui, quelles opérations, réussite/échec).
Partage vs NTFS sur un serveur de fichiers : ensembles indépendants ; l'accès effectif retient les autorisations les plus restrictives des deux. Les autorisations NTFS s'appliquent en local et à distance quel que soit le protocole ; les autorisations de partage seulement aux accès réseau. Approche fréquente : partage en Contrôle total pour Tout le monde, restriction par les autorisations NTFS.
Autorisations effectives : outil calculant les autorisations d'un utilisateur/groupe (appartenance aux groupes, héritage) ; évaluation locale, approximative (dépend du mode de connexion). « Afficher le contenu du dossier » (héritée par les dossiers seulement) et « Lecture & exécution » (héritée par fichiers et dossiers) semblent identiques mais s'héritent différemment. Le groupe Tout le monde n'inclut pas Ouverture de session anonyme par défaut.
Gestionnaire d'autorisations (Authorization Manager) : composant MMC, administration basée sur les rôles. Rôle = ensemble d'autorisations correspondant à une fonction (héritable). Tâche = ensemble d'opérations (et parfois d'autres tâches). Opération = petite action de niveau système/API (numéro entre 1 et 2^31-1). Rôles/tâches/opérations se définissent en mode développeur. Groupes : utilisateurs et groupes Windows ; groupes d'application (de base, de requêtes LDAP calculés en temps réel, de règle métier définis par script VBScript/JScript). Dans un groupe d'application de base, la non-appartenance prime sur l'appartenance.

5. EFS (Encrypting File System)
Chiffrement des fichiers et dossiers sur volumes NTFS (postes clients et serveurs de fichiers distants). Au premier chiffrement, EFS assigne au compte de l'utilisateur une paire de clés (privée et publique). Chiffrement via les attributs avancés (Explorateur) ou l'utilitaire en ligne de commande CIPHER ; propagation possible aux sous-dossiers. Sans la clé EFS, aucun accès au fichier chiffré même avec les autorisations. Chiffrement et compression NTFS mutuellement exclusifs.

6. COMPRESSION
Réduit la taille en supprimant les longues chaînes de zéros ; ne concerne que les données utilisateur (pas les métadonnées). Deux types :
- Compression NTFS : uniquement sur lecteur NTFS (fichiers, dossiers, volumes entiers) ; transparente (décompression/recompression automatique) mais baisse possible des performances. Règles de déplacement/copie identiques aux autorisations NTFS : toute copie ou déplacement depuis un autre lecteur NTFS compresse ; seul un déplacement au sein du même lecteur NTFS conserve l'état d'origine. Incompatible avec le chiffrement.
- Dossiers compressés (zippés) : sur FAT et NTFS ; restent compressés partout ; exécution de programmes et ouverture de fichiers directement possibles ; protection par mot de passe ; pas de baisse de performances ; compatibles avec d'autres logiciels de compression ; icône « tirette ».

7. QUOTAS, CLICHÉS INSTANTANÉS, DFS
Gestion de quota (Gestionnaire de ressources du serveur de fichiers, FSRM) : quotas limitant l'espace d'un volume ou dossier avec notifications ; quotas automatiques appliqués à tous les sous-dossiers présents et futurs ; modèles de quotas réutilisables. Seuils de notification (ex. 85 %) : courriel, journalisation, commande/script (dirquota.exe), rapport. Aucune notification par défaut.
Clichés instantanés de dossiers partagés : copies ponctuelles des fichiers d'une ressource partagée ; permettent de récupérer un fichier supprimé ou écrasé et de comparer des versions antérieures.
Espaces de noms DFS : représentation virtuelle des dossiers partagés d'une organisation (chemin de type UNC). Composants : serveur d'espaces de noms (membre ou contrôleur de domaine), racine (espace de noms de domaine : métadonnées dans AD DS ; peut être hébergée sur plusieurs serveurs), dossiers (avec ou sans cibles), cibles de dossiers (chemins UNC réels vers les données). Un client parcourant un dossier avec cibles reçoit une référence le redirigeant de manière transparente vers une cible (selon son site). Administration : composant Gestion DFS, commande DfsUtil, scripts WMI.
