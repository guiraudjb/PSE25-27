WINDOWS SERVER 2008 : SERVICES DHCP ET DNS

Depuis Windows 2000, Microsoft a choisi le DNS comme espace de noms stratégique en remplacement de NetBIOS ; sans DNS, Windows Server et Active Directory ne peuvent fonctionner. DHCP y est intégré : à chaque attribution d'adresse, le serveur DHCP peut inscrire le nom du client dans le DNS.

1. DHCP - GÉNÉRALITÉS
Origine : dérivé de BOOTP (RFC 951 et 1084 ; attribution dynamique d'adresses + démarrage à distance de stations sans disque). DHCP fournit en plus toutes les données de configuration TCP/IP.
Processus DHCPv4 en quatre étapes (messages en UDP) : découverte (DHCPDISCOVER, par diffusion) -> offre (DHCPOFFER) -> requête (DHCPREQUEST) -> accusé de réception (DHCPACK). Bail (lease) : durée fixée par l'administrateur ; renouvellement demandé à la moitié du bail ; à l'expiration, l'adresse retourne au pool.
Composants : serveurs DHCP (base de données des attributions et options ; adresse IP fixe obligatoire ; RFC 2132 pour les options), clients DHCP (RFC 2131), agents de relais DHCP/BOOTP (RFC 1542 ; routeur ou hôte qui relaie les diffusions vers des serveurs désignés, évitant un serveur par segment).
Base de données DHCP :
- Étendue (scope) : groupement administratif des plages consécutives d'adresses IP d'un sous-réseau physique ; à définir avant utilisation.
- Plage d'exclusion : adresses d'une étendue jamais proposées aux clients.
- Pool d'adresses : adresses restantes après exclusions, attribuées dynamiquement.
- Réservation : adresse à bail illimité liée à l'adresse MAC du périphérique (toujours la même IP).
- Options DHCP : paramètres supplémentaires attribués avec les baux (passerelle par défaut, serveurs WINS/DNS...) ; prédéfinies par la RFC 2132 ou personnalisées.

2. FONCTIONNALITÉS DHCP DANS WINDOWS SERVER
Intégration DHCP-DNS : le serveur DHCP peut agir en relais mandataire (proxy) et inscrire les RR A (directe) et PTR (inversée) pour ses clients, via l'option n°81 « Client FQDN » (le client communique son nom complet) et un message UPDATE. Modes : mise à jour suivant les requêtes des clients ; toujours mettre à jour (prioritaire sur le client) ; mise à jour pour clients non dynamiques (Windows 95/98/NT 4). Suppression des enregistrements à l'expiration du bail (par défaut).
Analyse et statistiques : alertes de seuil (ex. 90 % des adresses d'une étendue attribuées, pool épuisé) ; affichage graphique (adresses disponibles/épuisées, baux/s, offres, requêtes, ACK, NACK, refus, libérations).
Classes utilisateur : le client spécifie son type (bureau, portable...) ; le serveur attribue des options différentes (durée de bail, WINS, DNS...).
Attribution d'adresse multidiffusion : service MADCAP (adresses IP multicast partagées par un groupe).
Sécurité : un serveur DHCP doit être autorisé dans Active Directory (par l'administrateur du domaine) ; sinon aucune réponse aux requêtes.
Tolérance de panne : le fractionnement d'étendues fait perdre la moitié des adresses en cas de panne ; le clustering gère deux serveurs comme un seul système virtuel (un seul actif, base sur disque distant, reprise transparente).
Configuration automatique du client (depuis Windows 2000) : si aucun serveur DHCP n'est trouvé, le client s'auto-configure ; avec un ancien bail, il PING la passerelle par défaut du bail (succès = conserve le bail ; échec = déplacé, s'auto-configure et refait une recherche toutes les cinq minutes).
DHCPv6 : IPv6 configure ses adresses seul, mais DHCPv6 fournit une configuration d'adresse avec état ou d'autres paramètres. Drapeaux du routeur : M (à 1 : utiliser le protocole pour des adresses dynamiques), O (à 1 : pour d'autres paramètres). Infrastructure : clients, serveurs, agents de relais DHCPv6. Échange avec état (M et O à 1) : sollicitation -> information (le serveur peut fournir) -> demande -> réponse.
Déploiement : estimer le nombre de serveurs (routeurs, un serveur aux deux extrémités des liens WAN lents), délimiter les étendues (une par réseau physique, ou étendue globale pour multiréseaux), réservations pour serveurs WINS/DNS/contrôleurs de domaine/serveurs d'impression/clients Unix, tables BOOTP pour stations sans disque. Installation via le Gestionnaire de serveur -> Rôles -> Ajouter des rôles -> Serveur DHCP.

3. DNS - PRINCIPES
Résolution de noms = conversion noms d'hôtes <-> adresses IP. Avant 1984 : fichier HOSTS maintenu par le NIC, transmis par FTP (limites : bande passante, manque d'autonomie des organismes). DNS (1984) : base de données répartie, hiérarchique + protocoles (requête/mise à jour, réplication, schéma). Implémentation Microsoft : RFC 1034/1035 (NT 4.0) ; + RFC 1886, 1996, 1995, 2136, 2308, 2052 depuis Windows 2000.
Hiérarchie : racine (point), TLD (.com, .fr...), nœuds = noms de domaine, étiquette de 63 caractères max. FQDN = toutes les étiquettes séparées par des points, terminé par un point final ; profondeur max 127 niveaux, longueur max 255 caractères. « Domaine » = suffixe (sans l'hôte). Norme ISO 3166 pour les TLD pays.
Enregistrement de ressources (RR) : Nom de domaine (FQDN sinon relatif) ; TTL (durée de vie en cache, en secondes) ; type (16 bits) ; classe (IN = Internet, CH = chaotique) ; RDATA (données propres au type).
Types principaux : A (nom -> IPv4 32 bits), AAAA (nom -> IPv6 128 bits), CNAME (alias -> nom canonique), HINFO (descriptif CPU/OS, à éviter pour la sécurité), MX (serveur de messagerie, priorité 0-65535, plusieurs pour la redondance), NS (serveur de noms d'autorité), PTR (pointeur, résolution inverse), SOA (serveur d'autorité sur la zone + e-mail du contact, @ remplacé par un point). Spécifiques Windows : WINS, WINS-R.
Zones DNS : sections de la base réparties sur les serveurs de noms ; découpage par classes et par « coupes » dans l'espace de noms ; chaque zone a un nœud de plus haut niveau qui l'identifie. Données de zone : nœuds généraux, nœud supérieur, sous-zones, accès aux serveurs des sous-zones. RR clés : liste des serveurs de noms + RR SOA.
Types de serveurs (un serveur physique peut cumuler les rôles) :
- Primaire (maître) : autorité, fichier de zone en lecture-écriture, un par zone.
- Secondaire : données obtenues par transfert de zone, fichier en lecture seule, répond aux requêtes, secours du primaire, nombre illimité.
- Cache : base constituée des seules réponses reçues, aucune autorité, cache limité par le TTL.
Transfert de zone : les secondaires comparent le champ SERIAL du RR SOA (format année-mois-jour-version) avec le leur ; s'il a augmenté, ils rechargent. Types : total (toute la zone, trafic important), incrémental / IXFR (seuls les enregistrements modifiés), notification DNS (le primaire signale, le secondaire lance un transfert total ou incrémental).
Résolution de nom : le résolveur (intégré à l'OS) interface les applications aux serveurs de noms ; consulte son cache local ou des serveurs distants. Requête standard (RFC 1035) : champs QTYPE, QCLASS, QNAME ; UDP ou TCP.
- Mode itératif : le serveur répond sur ses seules informations locales (la réponse ou la référence d'un autre serveur) ; mode général sur Internet.
- Mode récursif : le premier serveur devient résolveur et fait toutes les requêtes ; mode des réseaux locaux, le plus sûr. Bits : RD (Récursion Désirée, marqué par le client), RA (Récursion Admissible, marqué par le serveur : disponibilité du service).
- Requêtes inverses : renvoient le nom d'hôte d'une IP connue ; domaine spécial in-addr.arpa (IP6.ARPA pour IPv6), enregistrements PTR. Requête PTR = question explicite « qui est a.b.c.d ? ».

4. FONCTIONNALITÉS DNS DANS WINDOWS SERVER
Ordre de résolution des noms d'hôtes (NetBIOS activé) : nom d'hôte local -> cache client DNS -> serveurs DNS configurés -> LLMNR (multidiffusion IPv4 et IPv6) -> cache de noms NetBIOS -> serveurs WINS -> diffusions NetBIOS -> fichier LMHOSTS. Arrêt à la première adresse trouvée.
Fonctionnalités du service DNS : conformité et interopérabilité RFC (BIND) ; implémentation pour Active Directory ; stockage des zones dans les partitions d'annuaire ; redirecteur conditionnel (transmet selon le nom de domaine de la requête) ; zones de stub (copie ne contenant que les RR identifiant les serveurs d'autorité d'une zone) ; intégration avec WINS et DHCP ; interface graphique (composant enfichable DNS, dnsmgmt.msc) et Dnscmd (scripts, administration distante) ; mise à jour dynamique (RFC 2136) ; transfert de zone incrémental ; mise à jour dynamique sécurisée (zones intégrées à Active Directory) ; nouveaux RR (SRV, ATMA) ; vieillissement et nettoyage des enregistrements ; chargement de zone en arrière-plan ; gestion IPv6 ; RODC ; zone GlobalNames.
Intégration DNS - Active Directory : les RR deviennent des objets de l'annuaire ; le transfert de zone est assuré par la réplication multi-maître d'Active Directory (plus de serveur primaire ; tout serveur DNS accepte les mises à jour) ; réplication sécurisée (zones plus en clair) ; permissions de sécurité sur les objets DNS ; seuls les serveurs DNS sur contrôleurs de domaine chargent ces zones. Représentation : objet conteneur DnsZone -> objets feuilles DnsNode -> attribut multi-valué DnsRecord.
Transfert de zone par incrément (IXFR) : par défaut sous Windows Server 2008 ; retour automatique au transfert complet avec un serveur DNS non compatible.
Mise à jour dynamique DNS (DDNS, RFC 2136) : OPCODE UPDATE, ajout/suppression de RR et test de prérequis, atomique. Nécessaire à cause de l'adressage IP dynamique (DHCP). La mise à jour doit être validée sur un serveur primaire (sauf zone intégrée à Active Directory, multi-maître). Le service client DHCP génère les mises à jour sur chaque poste (client DHCP ou IP fixe) ; par défaut le client met à jour A, le serveur DHCP met à jour PTR. Scénarios : client DHCP, client à configuration statique (met à jour A et PTR lui-même), client RAS (idem, tente de supprimer les RR avant de fermer la connexion). Réenregistrement : le serveur DHCP réinscrit ses RR au renouvellement du bail ; les clients Windows 2000+ réinscrivent toutes les 24 heures.
Mise à jour dynamique sécurisée (DNS intégré à Active Directory) : après refus d'une mise à jour non sécurisée, négociation d'un contexte de sécurité via Kerberos, vérification d'identité mutuelle, demande signée ; le serveur n'accepte que si le client a les autorisations. Réponses signées (une réponse usurpée est rejetée).
Enregistrement SRV (Emplacement du service, RFC 2052) : identifie les hôtes exécutant des services spéciaux. Sous Windows : LDAP (TCP 389), Kerberos (TCP 88), Kerberos Change Password (464), Global Catalog (TCP 3268/3286) et ports UDP correspondants. Inscrits dynamiquement par le service NETLOGON des contrôleurs de domaine. Champs : priorité (bas = prioritaire ; 0 pour Active Directory), poids (départage à priorité égale ; 100 pour Active Directory), port, FQDN de l'hôte. Localisateur de domaine (service Netlogon) : localise un contrôleur de domaine via le localisateur compatible IP/DNS (requête DNS puis LDAP UDP de vérification, mise en cache), sinon localisateur compatible Windows NT 4.
Chargement de zone en arrière-plan : threads de chargement des zones Active Directory pendant que le serveur répond déjà ; extraction ciblée depuis Active Directory pour une zone non encore chargée (évite l'indisponibilité, jusqu'à une heure, des grandes zones).
Gestion IPv6 : adresses 128 bits en notation hexadécimale ; résolution directe par AAAA, inverse par le domaine IP6.ARPA (chaque chiffre hexadécimal, inversé, = un niveau). dnscmd /config /EnableIPv6 nécessaire sous Windows Server 2003 ; IPv6 par défaut sous Windows Server 2008 (requêtes récursives vers serveurs IPv6, liste de transfert IPv4 + IPv6).
RODC (Read Only Domain Controller) : informations Active Directory en lecture seule, plus robuste aux attaques, installable sans sécurité physique garantie. Zone primaire DNS en lecture seule (modification uniquement sur un contrôleur non RODC).
Zone GlobalNames (Noms Globaux) : résolution de nom à étiquette unique via le DNS seul, pour un ensemble limité de serveurs centraux/critiques, en remplacement des enregistrements WINS statiques ; généralement des CNAME vers un FQDN ; unique dans la forêt, intégrée à Active Directory, copie locale sur chaque serveur d'autorité ; ne stocke pas les postes de bureau, pas de mises à jour dynamiques ; tous les serveurs DNS d'autorité doivent exécuter Windows Server 2008.
Choix des noms DNS : séparer les espaces de noms interne (privé, invisible de l'extérieur) et externe (public) pour éviter les ambiguïtés ; exclure le nom public enregistré pour l'usage interne (utiliser un suffixe différent ou un sous-domaine). Un domaine Active Directory porte un nom DNS ; les domaines enfants ont un nom immédiatement subordonné. Caractères DNS (RFC 1123) : A-Z, a-z, 0-9 et « - », insensible à la casse ; NetBIOS en admet davantage. Un poste Windows 2000+ a un nom NetBIOS (interopérabilité) et un nom complet DNS (nom d'hôte + suffixe DNS principal, par défaut le nom de domaine Active Directory).
Installation : adresse IP fixe obligatoire ; Gestionnaire de serveur -> Rôles -> Ajouter des rôles -> Serveur DNS ; console dnsmgmt.msc. Recommandations matérielles (2008) : Pentium II 400 MHz, 512 Mo de RAM par processeur, 4 Go de disque, carte réseau ; ~100 octets de RAM par enregistrement de ressource.
Pannes et diagnostics : NSLOOKUP (vérifier l'existence d'un serveur DNS, ses zones, la présence d'un RR, parcourir tous les enregistrements).
